# Issue #3：真实平台接入迭代

沿用 `feature/smart-shopping-engine` 和 Draft PR #2，保持 main 未合并。Notion、Drive 和最终验收由复核方处理。

本轮实现：

- 淘宝“访问异常”提示作为受限状态，停止商品详情与评价提取，防止返回残留证据。
- 详情读取限定在商品参数及 SKU 容器；显式参数保留文本和 CSS 来源。可选 SKU 与已选 SKU 分开，标题不填充品牌、型号；未选 SKU 不归属展示价。
- 评论保留正文、商品链接、采集时间、页面日期文本、提取选择器与证据编号；同商品相同正文去重。风险主题关联证据编号，仅表示用户报告的关注点；质量分保持 null。
- 同款候选分组纳入商品形态、包装数量及销售单位，展示商家和价格区间。缺失字段明确标记；候选组依然需要实物 SKU 确认。
- 开发板检索过滤标题明确指向外壳、裸屏、数字资源的候选，以及整鼠检索中的接收器等配件；过滤理由保留标题证据来源，不能代替参数核验。
- 一次研究默认读取候选详情及评价，报告已检查/缺失字段、平台覆盖及结算未验证状态。
- 工具声明为只读；本机 Codex 与 Hermes 均注册 `multimall`，复用用户授权的 `multimall-live` 浏览器会话，不复制凭据。

## 使用

新建 Codex 或 Hermes 会话后直接提出购物研究请求。Hermes 可用 `hermes chat -t multimall` 限定工具范围。浏览器 CLI 会话需要保持运行；若关闭，可用现有专用 Profile 登录方式。单工具超时设置为 900 秒，以容纳真实页面加载。

## 验收边界

渲染夹具用于检查防误合并和证据字段，并不能证明所有平台商品页布局已覆盖。四平台详情提取仍会因布局、折叠内容与访问限制而缺失；本轮不声称所有商品都已完成参数读取。

自动化检查覆盖访问限制残留评论、重复评论和后续故障描述、SKU 选项与选择状态、包装单位及商品形态误合并。实际客户端与第二品类采集结果见 [客户端验收](client-acceptance-2026-10-11.md)。

实站已定位京东当前 `.attribute .list .item` 参数容器，可读品牌、商品编号、货号及销售单位；型号、成色和未选 SKU 不补推。京东鼠标的泛化“型号=鼠标”不用于身份比较；显式国补备案型号作为另有来源的型号候选。

尚待验收：真实同 SKU 跨商家正例、各平台完整参数与评价覆盖、商家信誉规则复核、两品类的假阳性/漏匹配对照。得物、美团仍为人工入口，未宣称完成接入。
