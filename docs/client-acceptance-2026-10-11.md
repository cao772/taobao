## 鼠标实测暴露的问题与修复

第一次推荐混入两条闲鱼接收器；加入配件过滤。复跑发现“带无线 2.4G 接收器”的完整鼠标被误排；放宽完整包装表述并加入回归检查。随后将显式 M187p 型号从 M185 请求剔除。每项修复均来自真实返回标题，并有回归检查。标题只能提供排除线索，不能确认品牌、SKU、正品或成色。

最终 Hermes 实测：拼多多 M185 候选展示价 35.29 元（商家缺失），淘宝百亿补贴品牌优选 38 元、罗技正品外设店 39 元。商品列表会随检索变化；仅报告本次观测。前两条详情分别为 observed（无参数）及 verification_required，前一条评价为 no_visible_reviews；全部同款未确认，`review_sample_size=0`、`quality=no_visible_review_evidence`。四平台搜索成功不意味着详情或评价全部成功。

京东鼠标详情也读取到真实参数：品牌罗技（Logitech），标准“型号”字段仅写“鼠标”，国补备案型号写“M185”。解析器保留泛化分类原文，并将显式备案型号作为带来源的候选型号，见 [京东鼠标参数](evidence/jd-mouse-visible-parameters.json)；不从标题 M185/M186 推定 SKU，也不推定包装、成色或正品。

## 人工恢复后的复读

用户反馈详情恢复后，先读取当前页面而不导航，仍观察到可见的“访问异常提示”和“当前访问存在异常”；另一开发板详情也返回 verification_required。随后通过真实 MCP stdio 复读当前开发板详情与评价，均仍受限，评价 0 条，见 [恢复后工具返回](evidence/taobao-recovery-mcp.json)。用户随后确认是同一个 MultiMall 专用 Chrome 窗口，并提供截图；截图中的平台提示与 DOM 结果一致：详情访问仍存在限制，平台称正常访问方式恢复后还需一段时间自动恢复。因此不是会话选错的证据，当前不能验收为详情/评价已恢复。停止重复请求淘宝，保留会话及受限记录，不清除登录或绕过平台限制。

修复：商品已在当前页面打开时，详情与评价直接读取当前页，保留人工验证及展开的参数；不同商品仍正常导航，受限页面仍停止读取。CLI 在比较商品 URL 前只刷新 URL 元数据，不重新加载网页。新增回归检查覆盖同页不重载、异页导航及受限页保护；本地 54 项全部通过。
